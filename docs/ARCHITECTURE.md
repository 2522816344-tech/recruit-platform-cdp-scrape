## 关键设计

### 1. 不模拟登录

所有平台都依赖**你已登录的浏览器会话**。工具通过 CDP 远程调试端口（9222）复用那个会话，
而不是自己登录。这样既不存储密码 / Token，也不会触发登录态风控。

### 2. 每个平台独立标签页

为了避免相互干扰，每个平台的抓取脚本都：

1. 用 `pickOrCreate(host, url)` 找到或新建自己的标签页（**不要用 `pick`，找不到会中断整轮**）
2. 用 `__lpCards` / `__j51Cards` / `window.__INITIAL_STATE__.positionList` / BOSS 接口提取卡片
3. 用详情页 API 提取 JD

### 3. 节奏是硬性约束

每个平台都有 `pace[min, max]` 区间，脚本在两家公司之间随机取值。

- 猎聘：8-13 秒 / 家（风控最严）
- 智联：3-5 秒 / 家
- 前程无忧：2.5-4 秒 / 家
- BOSS：3-5.5 秒 / 家（但常被风控）

**不要**为了追求速度把这些值改小。

### 4. 平台间相互隔离 + 并发 ≤ 2

每个平台独占一个 Tab，互相不争抢。但**不要让 3 个以上平台同时跑**——浏览器过载会导致
详情页 `fetch` 整体卡死，表现为「JD 全空 + 岗位数偏低 + 每家 90s」。

### 5. 断点续抓

每家公司完成后立即 append 到 `data/<platform>_all.jsonl`。下次启动时只把 `ok=true`
的算完成（MISS/ERR 会重试）。`data/.progress_<platform>` 是当前正在抓哪家的心跳。

### 6. 公司名严格匹配

详见 `scripts/common.js`。核心思想：

- 2 字核心词会张冠李戴（`乐驰机器人` → `厦门乐驰食品`）
- 命中候选后还要用两级 `scopeOf` 隔离岗位池
- 跨行业词表（DOMAIN_BAD）防止命中食品 / 房地产 / 润滑油 等完全无关公司

### 7. 失败处理

- 风控：检测到验证码 / 短信验证 / 滑动验证 / `Loading...` → 暂停 + 提示
- 网络：3 次退避重试 + 换标签页
- 浏览器过载：标签页堆积 → `close_tabs.js` 清理后独占重跑
- 平台索引特性：智联「全文检索」会命中人力资源中介代发岗位，需用 `rejectTarget` 剔除
