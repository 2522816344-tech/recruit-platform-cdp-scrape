# 招聘平台批量抓取工具包

给一份公司名单，从 **猎聘 / 前程无忧 / 智联招聘 / BOSS直聘** 批量抓
「公司规模、性质·融资阶段、行业、岗位、城市、经验、学历、薪资、年薪结构、JD、福利」，
汇总成多 Sheet 的 Excel。

原理：复用你**已登录的浏览器会话**（通过 CDP 远程调试端口），不模拟登录、不绕验证码。
遇到人机验证就停下来等你手动过，而不是硬撞风控。

---

## 快速上手

### 1. 准备一个工作目录

脚本本体留在这里，**数据和工作目录分离**。随便建个目录，放两样东西：

```
我的调研/
├── companies.json     ← 公司名单（照 companies.example.json）
├── config.json        ← 可选，覆盖默认配置（照 config.example.json）
└── data/              ← 自动生成，结果都在这
```

`companies.json` 两种写法都行：

```json
["星辰传动", "云智动力"]
```

```json
[{ "n": "星辰传动", "kw": "星辰传动", "alt": "星辰", "must": "星辰" }]
```

- `n` 名单里的正式公司名（Excel 按它归组）
- `kw` 主检索词，**用简称命中率更高**（如 `海岳智能` 优于全称）
- `alt` 备选检索词，主词搜不到时自动换
- `must` 主体校验正则：命中的公司名必须含它，防止张冠李戴

### 2. 跑起来

```bash
cd 我的调研
node <本工具包路径>/run.js
```

它会依次：**启动浏览器 → 体检登录态 → 逐平台抓取 → 汇总出 Excel**。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `--platforms zhilian,liepin` | 只跑指定平台 |
| `--only 星辰传动,云智动力` | 定点重跑某几家公司 |
| `--limit 3` | 小样本试跑，先确认能通 |
| `--jobs 6` | 每家公司取几个代表性岗位 |
| `--parallel` | 各平台并行（默认串行，更稳） |
| `--no-build` | 只抓数据，不出表 |
| `--skip-chrome` | 不自动启浏览器（已在跑时用） |
| `--no-verify` | 跳过登录态体检 |

### 4. 断点续抓

数据按公司逐条 append 到 `data/<平台>_all.jsonl`，**只有成功的公司才算完成**。
中断了直接重跑，会自动跳过已成功的、重试没成功的。进度实时写在 `data/.progress_<平台>`。

想重抓某几家：先备份 jsonl，删掉对应行，再 `--only` 跑。

## 单独跑某一环

```bash
node chrome.js                      # 只启动浏览器
node chrome.js --init-profile       # 只复制登录态 profile
node verify.js                      # 只做登录态体检
node liepin.js --limit 2            # 只跑猎聘，抓 2 家试水
node j51.js                         # 前程无忧
node zp.js                          # 智联招聘
node boss.js                        # BOSS直聘（风控最严）
node patch_jd.js all --dry          # 统计各平台还缺多少 JD
node patch_jd.js all                # 慢速补抓缺失的 JD
node probe.js j51                   # 体检详情抓取（判断 JD 全空是过载还是被限频）
node close_tabs.js zhilian          # 清理某站点堆积的标签页
node open_tab.js https://we.51job.com/   # 新建一个标签页
python build_xlsx.py                # 只出表
```

各平台脚本都支持 `--only / --jobs / --limit`。

**JD 补抓**：主流程节奏偏快时详情页可能成片返回空 JD（不是没数据）。
`patch_jd.js` 只挑 `jd` 为空的岗位重抓，慢速 + 退避重试 + 每 15 条落盘，
支持 `job51` / `liepin`（这两家的 `detailUrl` 能反推出详情入口）。

**JD 全空先别急着补抓**：如果同时 `nJobs` 也偏小（如只有 1-4 条），大概率是
浏览器过载（多平台并发 + 标签页堆积）导致详情 `fetch` 整体卡死，
`fetchJD` 的重试会白烧 75s/家。先 `node probe.js j51` 确诊，再清标签页独占重跑。

## 环境变量

| 变量 | 说明 |
|---|---|
| `SCRAPE_DIR` | 工作目录，默认进程当前目录 |
| `SCRAPE_COMPANIES` | 名单路径，默认 `<工作目录>/companies.json` |
| `SCRAPE_CONFIG` | 配置路径，默认 `<工作目录>/config.json` |
| `SCRAPE_DATA` | 数据目录，默认 `<工作目录>/data` |
| `CDP_PORT` | 调试端口，默认 `9222` |
| `BROWSER_EXE` | 浏览器可执行文件（自动探测失败时手动指定） |
| `CHROME_PROFILE` | 抓取专用 profile 目录 |
| `CHROME_PROXY` | 需要走代理时填，不填则直连 |
| `SCRAPE_USER` | 账号用户名，用于登录态判定 |
| `LOCAL_CITY_RE` | 本地城市正则，覆盖 config 里的 `localCityRe` |
| `PYTHON` | 指定 python 解释器 |

## 各平台现状（实测）

| 平台 | 覆盖 | 备注 |
|---|---|---|
| 猎聘 | 好 | 会跳短信验证页，识别到即中止等你处理；节奏要放到 8–13s/家 |
| 前程无忧 | 好 | 最稳，适合当主力；偶发滑块 |
| 智联招聘 | 中 | `kw` 是全文检索（含 JD 正文），会命中大量人力中介代发岗位；不少公司确实 0 条，属平台索引特性 |
| BOSS直聘 | 差 | 风控最严，未登录/高频易触发 code 36；要登录态 + 很保守的节奏 |

**缺口补法**：先用前程无忧捞一遍，再用猎聘补，智联/BOSS 作补充。
全平台都没有的公司，多半是真的没在网上发对口岗位。

## 踩过的坑（改脚本前先看）

细节都在上层 `SKILL.md` 里，这里列最容易致命的几条：

1. **智联别传城市参数**。`jl=530` 是**北京**不是全国，不传 `jl` 才是全国超集。
2. **智联必须校验 `__INITIAL_STATE__.queryParams.kw` 已刷新**，否则会把上一次搜索的残留卡片当本次结果 —— 这是最大的假阳性来源。
3. **51job 搜索页会卡死在 `Loading...`**，同一个标签页重试永远失败，必须重置标签页引用 + 硬刷新。
4. **公司名匹配不能只看最长公共词**。2 字核心词会张冠李戴（`乐驰机器人` → `厦门乐驰食品`）。命中后还要用两级 `scopeOf` 隔离岗位池，否则同名的其它公司会被一起捞进来。
5. **各平台「万」的含义不同**：前程无忧/智联是月薪万，猎聘是年薪万。混用会让薪资差 10 倍。
6. **`nohup ... &` 会随工具调用结束被回收**；长跑要用后台任务 + 文件重定向（管道会缓冲，`tail` 看不到实时进度）。
7. **别让 3 个以上平台并发跑**，跨天长跑前先清标签页。浏览器一过载，详情 `fetch` 会整体卡死不返回 ——
   表现为「JD 全空 + 岗位数偏低 + 每家 90s」，很容易误判成被反爬。确诊/处置见上层 `SKILL.md` §7.2。
8. **列表卡片里就有经验/学历，一定要留下来**：`allJobs` 存
   `岗位名|薪资|城市|经验|学历` 五字段（早期只存前三段，出表时经验/学历覆盖率掉到 30%）。
9. **标签页要 `pickOrCreate` 而不是 `pick`**：只找不建的话，一旦标签页被关掉整轮抓取就 `NO_*_TAB` 中断。
